## 1. 接口设计约定

### 1.1 十条约定

**表 TAB-API-01　接口设计约定**

| # | 约定 | 取值 | 理由 / 出处 |
|---|---|---|---|
| 1 | 风格 | HTTPS + JSON，资源化 RESTful；资源名用**复数 + 连字符**（`/alarm-events`） | 复数表达集合语义；连字符与路径段可读性优于下划线 |
| 2 | 版本 | 路径前缀 `/api/v1`；不兼容变更升 `/api/v2`，v1 与 v2 并行 ≥ 6 个月 | 版本进路径而非 Header，便于 Nginx 侧按前缀限流与灰度 |
| 3 | 字段命名 | **报文字段与查询参数一律 `snake_case`**，与数据字典 §2.4 一致；路径参数写作 `{event_id}` | 避免「接口 camelCase、库 snake_case」的映射层，减少一处出错点 |
| 4 | 时间 | ISO 8601 带时区偏移（`2026-11-27T10:00:03.120+08:00`），毫秒精度；服务端内部存 UTC | 与数据字典 §6.1 一致；带偏移量避免「本地时间无时区」的歧义 |
| 5 | 数值与单位 | 数值为 JSON number；**字段名不带单位**，单位由 `unit` 字段随响应返回 | 单位随测点走（`point_def.unit`），接口不重复定义换算 |
| 6 | 枚举 | 存储值小写英文（`critical` / `major` / `minor`）；中文只在前端映射表 | 数据字典 §5 强制；禁止接口层出现中文字面量 |
| 7 | 未知枚举 | 客户端**必须忽略**不认识的枚举值并保留原值，不得整体报错 | 契约演进的前向兼容前提（见 §6.4） |
| 8 | 分页 | `page`（1 起）+ `page_size`（默认 20，告警工作台默认 50，上限 200）；响应含 `total` | 1 万条告警下组合筛选 ≤ 1 s（FR-M5-09）按 50 条分页验收 |
| 9 | 并发控制 | 台账 / 规则 / 事件的更新用 `If-Match: <row_version>`，不匹配返回 409 | `row_version` 已在数据字典各表定义，乐观锁无需另建字段 |
| 10 | 追踪 | 请求可带 `X-Request-Id`；响应必回 `X-Request-Id`，错误体必带 `trace_id` | NFR-TEST-04 要求单次告警可用 `trace_id` 串起全链路 |

### 1.2 统一错误体

采用 RFC 7807 风格的 `application/problem+json`。**只返回错误码与追踪号，不返回堆栈、SQL、内网路径**（SEC-C-07）。

```json
{
  "code": "CDCIM-RES-002",
  "message": "当前状态不允许该操作",
  "trace_id": "4f1c9b2e8a7d4c31",
  "details": [
    { "field": "event_status", "current": "closed", "allowed_next": [] }
  ]
}
```

`message` 为**面向人的短句**，可随文案调整；`code` 为**机读契约**，一经发布不得改语义（只增不改）。

### 1.3 状态码使用边界

| 码 | 只用于 | 不得用于 |
|---|---|---|
| 200 / 201 / 202 | 查询成功 / 创建成功 / 异步任务已受理 | — |
| 400 | 参数缺失、类型错、枚举越界、时间区间非法 | 权限问题（应 403）、资源不存在（应 404） |
| 401 | 未认证、令牌失效、会话超时、账号锁定 | 已认证但无权限（应 403） |
| 403 | 权限不足、职责分离冲突、AI 结果作控制入参 | 未登录（应 401） |
| 404 | 资源不存在或已归档 | 存在但无权访问（本项目按最小信息泄露原则**仍返回 403**，见 §4.3） |
| 409 | 状态机非法迁移、乐观锁冲突、幂等键复用、被引用不可删 | 参数格式错（应 400） |
| 413 / 422 | 查询或导出规模超限 / 语义校验失败（如导入存在错误行） | — |
| 429 | 限流 | — |
| 500 / 502 / 503 / 504 | 内部错误 / 外部平台异常 / 依赖不可用 / 外部超时 | 业务规则拒绝（应 4xx） |

## 3. OpenAPI 3.0 契约

以下 YAML 覆盖 11 个核心接口（登录、告警列表/详情/确认、曲线、实时值、规则创建、联动复核、重算、知识库问答、健康检查），其余 36 个按 §2 表格描述。**已通过 YAML 解析与 OpenAPI 3.0 规范级校验**；其中外部平台返回码等字段标注「协议待定（SRS Q-2）」，属当前无法闭合项。

```yaml
openapi: 3.0.3
info:
  title: CDCIM 动环智能监控平台 API
  version: 1.0.0
  description: |
    单入口 HTTPS 服务（仅 8080 对外）。认证采用服务端会话令牌（Bearer），
    非 JWT：会话可在服务端即时失效（改密、改角色、禁用账号）。
    字段命名 snake_case，与数据字典一致。时间为 ISO 8601 带时区偏移。
servers:
  - url: https://{host}:8080/api/v1
    variables:
      host:
        default: cdcim.local
        description: 内网访问地址，禁止公网暴露
security:
  - sessionToken: []
tags:
  - name: auth
    description: 认证与会话
  - name: alarm
    description: 告警查询与处置
  - name: point
    description: 测点与历史数据
  - name: rule
    description: 告警规则
  - name: linkage
    description: 联动控制
  - name: maintenance
    description: 数据修复与运维
  - name: ai
    description: 知识库问答
  - name: system
    description: 健康检查

paths:
  /auth/login:
    post:
      tags: [auth]
      summary: 登录并创建会话
      description: |
        连续 5 次失败锁定 10 min。失败提示统一为「账号或凭据错误」，不区分账号是否存在。
        管理员账号必须携带 otp_code。IdP 用户不校验本地口令。
      security: []
      requestBody:
        required: true
        content:
          application/json:
            schema:
              $ref: '#/components/schemas/LoginRequest'
      responses:
        '200':
          description: 登录成功
          headers:
            X-Request-Id:
              $ref: '#/components/headers/XRequestId'
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/LoginResponse'
        '400':
          $ref: '#/components/responses/BadRequest'
        '401':
          $ref: '#/components/responses/Unauthorized'
        '429':
          $ref: '#/components/responses/TooManyRequests'

  /alarm-events:
    get:
      tags: [alarm]
      summary: 告警事件列表
      description: |
        服务端分页，默认 50 条。组合筛选在 1 万条数据下 P95 ≤ 1 s。
        排序默认 last_occur_at DESC，与索引 idx_alarm_event_status 同向。
      parameters:
```

**YAML 的三处取舍**（评审常问）：

1. **参数与 schema 全部给 `$ref` 而非内联**。47 个接口若内联，`alarm_level` 的枚举会在 10 处重复，改一次要改十处——这正是共享内核「只放码值」的落地方式。
2. **`AckRequest` 必填 `expected_status`**。它把「客户端认为的状态」显式带入，服务端可据此区分「重复提交」与「状态已被他人改变」，两种情形返回不同 `details`，便于值班员判断是该刷新还是该找同事。
3. **`SeriesResponse.route` 必须回显**。查询的真正风险不是慢，而是**路由判错**：180 天请求若落到原始表，8 个测点叠加约 8.3 s（容量文档 TAB-ARCH-168），必然超时。回显 `route` 让前端与压测脚本能直接断言「这次走对了表」。

## 4. 鉴权与权限

### 4.1 认证载体

**服务端会话令牌（opaque token），不是 JWT。** 选型理由是可即时失效：改密、改角色、禁用账号后必须让旧令牌立即 401（SEC-A-04 的验收判据），而 JWT 在过期前无法撤销。会话存 Redis（`cdcim:sess:*`），空闲 30 min、绝对 8 h，单账号并发 ≤ 3。

> **一处须登记的口径差异**：[安全架构 SEC-A-04](../03-架构/11-安全架构与等保对照.md) 已明确「api-service 会话管理 + Redis 会话索引」，本文沿用；但[数据字典 §4.21](../02-需求/08-数据字典初稿.md) 声明「Redis 中不存任何不可重建的数据（8 类键全部可重建）」。会话键是**第 9 类键**，且不可重建——丢失只导致全员重新登录，不影响任何业务事实，因此不违背该条约束的**本意**（业务事实不丢），但字面上需在字典升版时把「8 类」改为「9 类」并注明例外。这不是待确认项，而是一处待回写的文档对齐。

### 4.2 401 / 403 判定顺序

**表 TAB-API-06　认证与授权的判定顺序（自上而下，命中即返回）**

| 序 | 判定 | 结果 | 错误码 | 是否记审计 |
|---|---|---|---|---|
| 1 | 无 `Authorization` 头，或 scheme 非 `Bearer` | 401 | `CDCIM-AUTH-001` | 否（避免噪声；同 IP 连续 20 次则记） |
| 2 | 令牌格式合法但会话不存在（已登出 / 已过期 / 已清理） | 401 | `CDCIM-AUTH-002` | 否 |
| 3 | 空闲 > 30 min 或会话总时长 > 8 h | 401 | `CDCIM-AUTH-003` | 否 |
| 4 | 账号 `disabled` / `locked`（失败 5 次锁 10 min） | 401 | `CDCIM-AUTH-004` | 是（`operation_result=denied`） |
| 5 | 权限点未命中，或 `role_permission.effect='deny'` 命中 | 403 | `CDCIM-AUTH-005` | 是（`risk_level` 视动作定） |
| 6 | 职责分离冲突：复核人 = 确认人；或账号同时持有 `door_control` 互斥组两权 | 403 | `CDCIM-AUTH-006` | 是（high） |
| 7 | 请求体携带 `source=ai_advice` 的控制类入参 | 403 | `CDCIM-AUTH-007` | 是（high） |
| 8 | 数据范围越界（`role.data_scope=room` 且跨机房） | 403 | `CDCIM-AUTH-005` | 是 |
| 9 | 资源不存在或已归档 | 404 | `CDCIM-RES-001` | 否 |
| 10 | 业务校验（状态机、乐观锁、引用完整性） | 409 / 422 | 见 §5 | 是（状态机拒绝必记） |

三条必须说清的规则：

1. **认证先于授权，授权先于业务校验。** 若把「资源是否存在」放在授权之前，越权者可通过 404/403 的差异枚举出资源是否存在；本项目统一先判权限，无权即 403，不做资源探测。
2. **`deny` 优先于 `grant`。** 这是「默认拒绝」在数据层的表达（数据字典 §4.19）：先查 `effect='deny'`，命中即拒，再查 `grant`。
3. **所有 403 必写审计**，含操作人、角色快照、对象、来源 IP、会话 ID（NFR-SEC-02 要求「越权请求 100% 返回 403 并记审计」）。审计写入失败时按 fail-closed 处理：**拒绝该请求并返回 503**，不放行。

### 4.3 三处易错点

| # | 易错点 | 正确做法 | 若不这样做 |
|---|---|---|---|
| 1 | 把「管理员」当成超级角色 | 管理员**无** `alarm:ack`、`rule:write`、`device:write`、`linkage:policy_write` | 管理员可确认告警，则「删审计掩盖误确认」的动机成立（矩阵第 4 行说明） |
| 2 | 门禁提交与复核放在同一角色 | 值班员/工程师提交，**仅管理员复核**，且复核人 ≠ 确认人（DB CHECK 约束兜底） | 单人闭环「改策略 + 批准放行」，物理安全失控 |
| 3 | 认为前端隐藏按钮等于无权限 | 每个写接口在服务端独立校验；前端隐藏只是易用性 | 直接构造请求即可越权（NFR-SEC-02 的 40 条用例正是这么造的） |

## 5. 错误码表

**表 TAB-API-07　错误码与处理建议（26 条）**

| 错误码 | HTTP | 含义 | 处理建议 |
|---|---|---|---|
| `CDCIM-REQ-001` | 400 | 请求参数缺失或格式错误 | 按 `details[].field` 修正后重试 |
| `CDCIM-REQ-002` | 400 | 枚举值不在定义域（含 `alarm_level` 第四级） | 取数据字典 §5 的枚举值 |
| `CDCIM-REQ-003` | 400 | 时间区间非法（`start ≥ end`、缺时区、跨度超 180 天） | 修正区间或拆分查询 |
| `CDCIM-REQ-004` | 409 | 乐观锁冲突（`row_version` 不匹配） | 重新 GET 取最新版本后重试 |
| `CDCIM-REQ-005` | 409 | 同一 `Idempotency-Key` 用于不同请求体 | 换新键；确属重试则原样重发 |
| `CDCIM-REQ-006` | 413 | 查询或导出规模超限（点数、行数、区间） | 缩小范围或交由服务端降采样 |
| `CDCIM-REQ-007` | 429 | 触发限流 | 按 `Retry-After` 退避，禁止立即重试 |
| `CDCIM-AUTH-001` | 401 | 未提供凭据或 scheme 非 Bearer | 重新登录 |
| `CDCIM-AUTH-002` | 401 | 令牌无效、已登出或会话已清理 | 重新登录 |
| `CDCIM-AUTH-003` | 401 | 会话超时（空闲 30 min / 绝对 8 h） | 重新登录 |
| `CDCIM-AUTH-004` | 401 | 账号锁定（连续失败 5 次，锁 10 min）或已禁用 | 等待解锁或联系管理员 |
| `CDCIM-AUTH-005` | 403 | 权限不足（含 deny 优先命中、数据范围越界） | 向管理员申请对应功能点授权 |
| `CDCIM-AUTH-006` | 403 | 职责分离冲突（复核人 = 确认人，或互斥权限并存） | 由他人复核；解除冲突授权 |
| `CDCIM-AUTH-007` | 403 | AI 建议被当作控制入参 | 移除 `source=ai_advice` 字段，由人工确认后提交 |
| `CDCIM-RES-001` | 404 | 资源不存在或已归档 | 核对 ID；归档数据需走归档查询 |
| `CDCIM-RES-002` | 409 | 状态机非法迁移 | 按 `details[].allowed_next` 选择合法动作 |
| `CDCIM-RES-003` | 409 | 资源被引用不可删除（`ON DELETE RESTRICT`） | 改为 `lifecycle_status=retired` 退役 |
| `CDCIM-DATA-001` | 409 | 投运后禁止变更换算系数 / 偏移 | 新建测点并迁移绑定点位（逻辑视图不变式 #1-②） |
| `CDCIM-DATA-002` | 422 | 测点模板导入存在错误行 | 按返回的行号与原因修正后整体重导（不做部分成功） |
| `CDCIM-EXT-001` | 502 | 门禁平台不可用或返回异常 | 记录置 `failed` 并生成 `linkage_failure` 告警；告警推送不受影响 |
| `CDCIM-EXT-002` | 504 | 视频平台取流超时（5 s） | 回落抓拍；仍失败提示人工重试 |
| `CDCIM-EXT-003` | 503 | 大模型 / 向量库不可用（旁路降级） | 展示规则侧根因，界面标注「AI 建议不可用」 |
| `CDCIM-SYS-001` | 500 | 服务内部错误 | 凭 `trace_id` 报障；不重试写操作（先用幂等键确认结果） |
| `CDCIM-SYS-002` | 503 | 依赖不可用（PG / TDengine / Redis） | 只读链路允许降级；写操作按 fail-closed 拒绝后重试 |
| `CDCIM-SYS-003` | 503 | 重算任务并发已满或不在 02:00–05:00 窗口 | 排队或改至窗口内提交 |
| `CDCIM-SYS-004` | 503 | 审计写入失败（审计不可用即拒绝写操作） | 联系管理员；此时系统对写操作整体 fail-closed |

> 错误码分层含义：`REQ` 请求侧、`AUTH` 认证授权、`RES` 资源与状态机、`DATA` 数据规则、`EXT` 外部平台、`SYS` 自身与依赖。**客户端可按前缀做统一兜底**（如 `AUTH-*` 一律跳登录页），不必逐个枚举。

## 6. 限流与幂等

### 6.1 限流

**表 TAB-API-08　限流阈值（与 SEC-V-01 一致）**

| 接口组 | 阈值 | 维度 | 依据 / 说明 |
|---|---|---|---|
| `/auth/login` | 5 次 / 5 min | IP | 抗口令爆破（SEC-A-02）；超限返回 429 且不区分账号 |
| `/auth/refresh` | 30 次 / min | 会话 | 前端 15 min 续期一次，30 次留冗余 |
| 只读查询（列表、详情、实时值） | 120 RPM | 用户 | 值班终端并发 ≤ 10，单用户 2 QPS 足够 |
| 历史曲线 | 30 RPM；单用户并发 2 | 用户 | 大区间查询占磁盘读带宽，与写提交争同一队列（容量文档 §5 第 2 项） |
| 导出（审计 / 报表） | 1 次 / 10 min | 用户 | SEC-V-01；同时受「全量导出需审批」约束（SEC-Z-05） |
| 联动下发 | 10 次 / 日 | 全局 | IF-EXT-05 的频次上限；门禁平台侧限流更严 |
| AI 调用 | 5 QPS；5000 次 / 日 | 全局 | FR-M6-09；超限后仅保留紧急告警的建议生成 |
| 重算 | 并发 1；单次区间 ≤ 7 天；02:00–05:00 | 全局 | 避免与备份（01:00）、归档（03:00）争磁盘（进程视图 §8 排期） |
| `POST` 写操作（其他） | 60 RPM | 用户 | 批量确认走专门的批量接口，不靠提高单接口频次 |

限流实现放两层：Nginx 按 IP 做粗粒度（登录、导出），应用层按「用户 + 接口组」做令牌桶。**超限一律 429 并带 `Retry-After`**，不得静默排队——排队会让值班员误以为操作已生效。

### 6.2 幂等

**表 TAB-API-09　`Idempotency-Key` 使用规则**

| 项 | 规则 |
|---|---|
| 必带接口 | `POST /linkage-records`、`/confirm`、`/review`、`/compensate`、`/maintenance/recompute`、`/audit-logs/export`、`/reports/export` |
| 可选接口 | 其他 `POST`；不带则按「每次都是新请求」处理 |
| 键格式 | UUID v4，客户端生成（联动场景与 `linkage_record.request_id` **同值**，不另生成） |
| 去重作用域 | `actor_id + method + path`，避免不同用户撞键 |
| 去重窗口 | 24 h（与 `request_id` 的服务端去重窗口一致） |
| 重放语义 | 返回**首次的状态码与响应体**，附 `Idempotent-Replay: true`；不重复执行、不重复记审计 |
| 同键异体 | 返回 409 `CDCIM-REQ-005`，不放行 |
| 存储 | Redis，键 `cdcim:idem:{actor_id}:{key}`，TTL 24 h；值存状态码 + 响应体摘要 |

**为什么联动必须带**：门禁「常开」是物理动作，重复执行意味着门被反复驱动。仅靠状态机不够——第一次请求超时（客户端没收到响应）时记录已是 `executing`，客户端重试会被状态机拒绝，但**真正的问题是该不该重试**：带幂等键时客户端可安全重试并拿到首次结果，不带时只能人工查记录。这是 FR-M4-05「同一 request_id 只执行 1 次」在接口层的落点。

## 论文可引用段落

> **【适用题目类型】论信息系统的接口设计 / 论系统集成 / 论软件架构设计**

接口设计的难点不在定义路径，而在把「谁能做什么、失败时怎样」写成机器可判定的规则。我为 47 个接口先定十条约定：版本进路径、字段用下划线以与数据库同名、时间强制带时区、未知枚举必须忽略。授权没有停在「三角色」的表述上，而是把认证与授权拆成十步判定顺序：先认证、再授权、最后业务校验，默认拒绝优先于显式授予。直接收益是越权用例可以穷举——每条用例的期望响应码唯一，不会出现「有时 403 有时 404」的争议。最容易被忽略的是两个接口：降采样重算源于架构走查发现的「补传保证明细不丢、聚合却不会自动修正」，不提供它，「零丢失」在验收时站不住；曲线查询则必须回显路由，因为查询的真正风险不是慢，而是判错——180 天请求若落到原始表，八点叠加要八秒以上。

（约 290 字）
