## 2. 业务背景与现状痛点

数据中心承载全行核心业务系统运行，动力与环境（简称「动环」）是业务连续性的物理底座。现有动环监控体系存在五个痛点，构成本项目的立项依据：

| # | 现状痛点 | 业务影响 |
|---|---|---|
| 1 | **厂商锁定、系统割裂**：UPS、精密空调、门禁、漏水各自独立平台，各厂商私有协议与私有云 | 无法统一视图，故障时需在 4–5 个系统间切换排查 |
| 2 | **告警风暴**：单次市电波动可在 3 分钟内触发 200+ 条告警，无根因聚合 | 值班人员告警疲劳，真实故障被淹没 |
| 3 | **被动响应**：阈值告警为主，缺乏趋势预测与容量预判 | 精密空调制冷量不足只能事后发现 |
| 4 | **数据孤岛**：历史数据仅存 7 天，无法做长期能效分析与审计追溯 | 不满足等保三级日志留存 6 个月要求 |
| 5 | **巡检依赖人工**：每日 2 次现场巡检、手工填表 | 人力成本高，数据不可信、不可追溯 |

## 3. 建设目标

### 3.1 业务目标（论文「实施效果」段落的量化基线）

| 指标 | 现状 | 目标值 | 度量方式 |
|---|---|---|---|
| 告警平均响应时间 | 8 min | ≤ 1 min | 告警产生 → 值班确认的时间差 P95 |
| 告警误报/重复率 | 约 65% | ≤ 20% | 归并后有效告警占比 |
| 故障根因定位时长 | 25 min | ≤ 5 min | 从告警到定位到具体设备的时长 |
| 数据留存周期 | 7 天 | ≥ 180 天（原始）+ 3 年（降采样） | 库内可查范围 |
| 日常巡检人工 | 2 人·次/日 | ≤ 0.5 人·次/日 | 自动巡检替代率 |
| 系统可用性 | — | ≥ 99.99%（年停机 ≤ 52.6 min） | 拨测 + 自身监控 |

### 3.2 技术目标

1. 统一接入：支持 Modbus TCP / SNMP / MQTT 三类协议，测点规模可横向扩展。
2. 实时性：采集到入库端到端 P99 ≤ 2 s；告警判定时延 P99 ≤ 3 s。
3. 高可用：核心链路无单点，任一组件故障不影响数据不丢（至少一次投递 + 幂等写入）。
4. 安全合规：等保 2.0 三级，数据不出内网（大模型能力走脱敏外发通道）。
5. 信创适配：时序库、操作系统、中间件具备国产化替代路径。
6. 可视化：2D 总览大屏 + 3D 机房数字孪生，支持告警空间定位。

## 4. 建设范围

**范围内**

- 动力：UPS、配电柜/列头柜、蓄电池组、柴油发电机（遥测遥信）
- 环境：温湿度、漏水、烟感、空气质量
- 暖通：精密空调、冷通道/热通道、加湿除湿
- 安防联动：门禁、视频（仅对接与联动，不重建视频平台）
- 能力：实时采集 → 消息接入 → 流式计算 → 时序存储 → 告警研判（分级/抑制/根因）→ 联动控制 → 2D/3D 可视化 → 报表与审计
- AI 增强：告警降噪聚类、根因建议、运维知识库问答（RAG）、自然语言查询

**范围外（明确不做，避免摊大饼）**

- IT 设备监控（服务器/存储/网络性能）与 CMDB 资产台账
- 视频智能分析算法（仅做告警联动调用）
- 计费、工单系统（仅提供接口对接）
- 移动端 App（响应式 Web 为准）

## 5. 建设规模与容量估算

> 论文「架构设计」与「容量规划」段落的数字来源。以下为**草案值**，需按真实情况校正。

| 项 | 草案值 | 说明 |
|---|---|---|
| 机房数量 | 3 个（同城，主/备/灾备） | 〔待确认〕 |
| 机柜总数 | 3 个机房合计约 120 个机柜（单机房约 40 个） | 〔待确认〕 |
| 测点总数 | 约 2000 点 | 〔待确认〕 |
| 采集周期 | 5 s（快变遥测）/ 30 s（慢变遥信） | 分频采集，降负载 |
| 数据速率 | 2000 ÷ 5 = **400 点/秒**，约 **3456 万条/天** | 峰值按 1.5 倍计 600 点/秒 |
| 单条记录 | 约 64 B（设备 ID + 测点 + 值 + 质量码 + 时间戳） | — |
| 原始数据量 | 约 **2.2 GB/天** | 400 × 86400 × 64 B |
| 压缩后（列存 1:10） | 约 **220 MB/天** | TDengine 列存 + 差分编码 |
| 留存 180 天 | 约 **40 GB** | 原始精度 |
| 三年降采样（1 min） | 约 **12 GB** | 长期趋势与审计 |
| 消息峰值吞吐 | 600 msg/s，按 3 倍冗余设计 1800 msg/s | 单节点 Redpanda 可承载 |

**结论**：单机 WSL + Docker 在 8 GB 内存配额下可承载本原型全链路；生产环境按 3 节点集群规划，容量规划文档在 P2 补充。

> 2025 年初，我所在单位启动数据中心动力与环境智能监控系统建设项目，由我担任技术负责人兼系统架构师。该数据中心承载全行核心业务系统运行，共 3 个机房、约 120 个机柜、2000 余个动环测点，采集周期 5 秒，日均产生遥测数据约 3500 万条。此前动环监控由 UPS、精密空调、门禁、漏水四家厂商的独立平台分散承担，协议与数据互不联通，单次市电波动可在三分钟内触发两百余条无关联告警，值班人员需在多个系统间切换排查，故障根因定位平均耗时 25 分钟；同时历史数据仅保留 7 天，无法支撑能效分析与等保三级日志留存要求。项目目标是建成统一的采集、存储、告警研判与可视化平台，将告警响应时间压缩至 1 分钟以内、重复告警率降至 20% 以下，并在满足数据不出内网的前提下引入大模型辅助研判，将系统年可用性提升至 99.99%。
