## 1. 约束分类与效力

| 类别 | 含义 | 违反后果 | 可否协商 |
|---|---|---|---|
| **硬约束（H）** | 不可违反，违反即方案作废 | 架构需重构 / 合规不通过 | 否 |
| **软约束（S）** | 目标值，可权衡 | 指标不达标但可上线 | 是，需记 ADR |

> 下文每条标注 `H` 或 `S`。硬约束一旦变更，必须走变更控制流程并留 ADR。

## 2. 环境与资源约束

| # | 类别 | 约束 | 级别 | 对架构的强制影响 |
|---|---|---|---|---|
| C-01 | 环境 | 本地原型运行于 WSL2 + Docker，**内存配额 8 GB，硬上限 10 GB** | H | 组件必须轻量化：选 Redpanda 而非 Kafka 集群、Flink 只能按需 profile 启动 |
| C-02 | 环境 | 无 GPU，显卡为集显 | H | 大模型不得本地部署；3D 渲染必须做 LOD 与实例化 |
| C-03 | 环境 | 单机部署，非集群 | H | 高可用通过「进程级多副本 + 快速重启 + 数据不丢」表达，不做节点级容灾 |
| C-04 | 环境 | 两台设备（工作/家庭）同构，均 WSL2 + Docker | H | 禁止绝对路径；配置外置 `.env`；数据卷不入库 |
| C-05 | 环境 | 镜像拉取需可访问容器镜像仓库，可能需国内加速 | S | compose 中镜像地址集中在单一文件，便于替换加速源 |
| C-06 | 环境 | 宿主端口可能被占用（3000/8080/9090 常见冲突） | S | 端口全部由 `.env` 驱动，支持整体偏移 |
| C-07 | 环境 | Windows 侧浏览器需经 `localhost` 访问 WSL 内服务 | H | Web 端口绑 `0.0.0.0`，其余绑 `127.0.0.1` |

## 3. 合规与安全约束

| # | 类别 | 约束 | 级别 | 对架构的强制影响 |
|---|---|---|---|---|
| C-08 | 合规 | 等保 2.0 三级要求：身份鉴别、访问控制、安全审计、入侵防范、数据完整性与保密性、备份恢复 | H | 需统一认证与 RBAC、全量操作审计表、双向 TLS 可选、备份脚本 |
| C-09 | 合规 | 金融数据**不出内网**；送外部大模型的必须是脱敏后的抽象数据 | H | AI 层必须串接脱敏中间件，设备编号哈希化、拓扑抽象为逻辑 ID |
| C-10 | 合规 | 审计日志留存 ≥ 6 个月，不可篡改 | H | 审计表只追加、禁改禁删；归档策略独立于业务数据 |
| C-11 | 合规 | 信创导向：优先国产数据库/中间件，保留替代路径 | S | TDengine（国产时序库）为主选；OS/中间件给出替代对照表 |
| C-12 | 安全 | 大模型输出不得直接驱动控制指令 | H | 联动控制必须经规则授权或人工确认（人在回路） |
| C-13 | 安全 | 密钥、模型 API Key 不得入库、不得进日志 | H | `.env` 隔离 + 日志脱敏规则 |

## 4. 业务与技术约束

| # | 类别 | 约束 | 级别 | 对架构的强制影响 |
|---|---|---|---|---|
| C-14 | 业务 | 7×24 运行，监控系统自身不可成为故障源 | H | **AI 与 3D 均不得进入告警主链路**；主链路零外部依赖 |
| C-15 | 业务 | 告警判定时延 P99 ≤ 3 s，采集到入库 P99 ≤ 2 s | S | 流式计算就近处理，禁止同步调用外部服务 |
| C-16 | 业务 | 数据不丢：至少一次投递 + 幂等写入 | H | 消费者手动提交位点、时序库按时间戳幂等覆盖 |
| C-17 | 业务 | 测点规模可扩展至万级（当前 2000） | S | 分区键按机房 + 设备类型设计，避免热点 |
| C-18 | 业务 | 必须支持 Modbus TCP / SNMP / MQTT 三类协议接入 | S | 采集网关做协议适配层，参数化配置 |
| C-19 | 技术 | 不引入需要 JDK 的常驻组件（Flink 除外，按需） | S | 计算层用 Python 实现，减少常驻内存 |

## 6. 范围约束（明确不做）

| 不做 | 理由 |
|---|---|
| IT 设备监控与 CMDB | 与本项目动环主题不同源，且工作量吞没备考时间 |
| 视频智能分析算法 | 仅做告警联动调用，不重建视频平台 |
| 移动端 App | 响应式 Web 已覆盖；App 上架流程与合规成本高 |
| 工单与计费系统 | 通过接口对接，不重复建设 |
| 板卡级 3D 建模 | 三角面数超百万，无 GPU 环境不可行，且运维价值低 |

## 7. 诚实边界：单机环境不可验证项

> 论文中这些内容**只能写「设计约束与架构战术」**，不得写成「已实现/已实测」。这是论文红线：虚构实测数据属「明显不真实」。

| # | 不可验证项 | 真实场景做法 | 本项目替代方案 | 论文写法 |
|---|---|---|---|---|
| B-01 | 等保三级合规**认证** | 第三方测评机构现场测评 | 输出《等保三级要求对照表》，逐条给架构落点 | 「设计满足等保三级要求，认证由第三方测评完成，不在本文范围」 |
| B-02 | 真实 Modbus/SNMP 硬件对接 | 边缘网关对接 UPS/空调厂商设备 | 协议模拟器（Modbus 从站 + SNMP Agent），报文格式与真实设备一致 | 「以协议模拟器验证接入能力，生产环境替换为边缘网关」 |
| B-03 | 异地双活 / 跨机房容灾 | 双活数据中心 + 数据同步 | 仅做同机多副本 + 备份恢复演练 | 「灾备为设计章节内容，未在原型中验证」 |
| B-04 | 百万测点压测 | 多节点集群 + 压力测试平台 | 压测至 2000 测点 3 倍冗余（1800 msg/s） | 「按 1800 msg/s 验证，万级规模按容量规划推导」 |
| B-05 | 信创全栈适配 | 鲲鹏/飞腾 + 麒麟 OS + 达梦/人大金仓 | 给出替代对照表，TDengine 本身为国产 | 「给出信创适配路径，未做全栈验证」 |
| B-06 | 大模型效果的客观评价 | 人工标注集 + 准确率评估 | 小规模样本集（100 条历史告警）做定性评估 | 「在 100 条样本上人工评估，非严格基准测试」 |

## 论文可引用段落

> 本段适用于「架构设计」「系统可靠性」「安全架构」类论文的约束分析部分。
>
> 本项目在架构设计之初即明确了三类硬约束。其一是资源约束：原型环境仅有 8 GB 内存且无独立显卡，这意味着任何以集群形态出现的中间件都会挤压业务进程，也意味着无法本地部署大模型。其二是合规约束：作为金融行业数据中心系统，需满足等保 2.0 三级要求，且生产数据不得离开内网，任何引入外部智能服务的设计都必须先解决数据脱敏问题。其三是业务约束：动环监控系统本身是业务连续性的保障设施，绝不能因为自身依赖外部服务而成为新的故障源。这三条约束直接决定了后续两项关键决策——大模型能力以旁路方式接入而非嵌入告警主链路，可视化采用机房级实例化渲染而非全要素建模。我认为，架构设计的本质不是选择最多的技术，而是在约束边界内找到代价最小、且能被清楚解释的那一个。
