# 多设备同步规程（Multi-Device Sync Protocol）

| 项 | 内容 |
|---|---|
| 文档编号 | CDCIM-SPEC-04 |
| 版本 / 状态 | v1.0 · 生效 |
| 适用范围 | 工作 / 家庭两台开发设备（均为 WSL2 + Docker） |
| 上游依据 | [约束清单 C-04](../01-立项/06-约束清单.md) |

---

## 1. 同步载体

| 项 | 值 |
|---|---|
| 远端仓库 | `git@github.com:smornfly/CDCIM.git`（私有，SSH） |
| 主分支 | `main`（唯一长期分支，单人开发不需要 feature 分支） |
| 认证 | SSH key（`~/.ssh/id_rsa`），两台设备各自配置公钥 |
| 同步粒度 | 每个**阶段验收通过后**提交并打 tag；日常可多次小提交 |

**为什么不用分支策略**：单人、单线程、串行阶段，分支只会带来合并成本。用「小提交 + 阶段 tag」更简单可控。

## 2. 换设备标准动作

### 开始工作前

```bash
cd ~/CDCIM            # 或 E:/FileFolder/workbuddy/rkwork/CDCIM
git pull --rebase
cat docs/00-项目状态与门禁.md     # 先看上下文，别凭记忆
```

### 结束工作后

```bash
git add -A
git commit -m "docs(P1): 完成质量属性场景表与效用树"
git push
```

> **铁律：不留未提交的跨天改动。** 两台设备同时持有未提交改动是冲突的唯一来源。

---

## 3. 提交信息规范

格式：`<类型>(<阶段>): <一句话说明>`

| 类型 | 用途 | 示例 |
|---|---|---|
| `docs` | 文档 | `docs(P2): 补充 ATAM 评估报告权衡点表` |
| `feat` | 新功能 | `feat(P4): 采集网关支持 Modbus 批量读取` |
| `fix` | 修缺陷 | `fix(P5): 修正告警抑制键未按设备维度隔离` |
| `chore` | 构建/配置 | `chore(P4): 调整 compose 内存限制` |
| `refactor` | 重构 | `refactor(P5): 抽出脱敏中间件为独立模块` |

**要求**：一次提交只做一件事；文档与代码不混提；提交信息写「做了什么」，不写「update」。


## 5. 冲突处理

```bash
git pull --rebase
# 若冲突：
git status                       # 看冲突文件
# 手工编辑解决，保留双方有效内容
git add <file>
git rebase --continue
git push
```

**冲突高发区与预防**

| 文件 | 冲突原因 | 预防 |
|---|---|---|
| `docs/00-项目状态与门禁.md` | 两端都改状态 | 只在阶段边界修改；改前先 pull |
| `docs/09-决策/决策台账.md` | 两端追加决策 | 追加到表尾，绝不改动他人已写行 |
| `README.md` | 两端改状态表 | 状态只在阶段边界改 |
| `*.json/*.yml` | 格式化差异 | 统一 2 空格缩进，提交前不跑自动格式化 |

## 6. 禁止入库的内容

| 内容 | 原因 | 处理 |
|---|---|---|
| `.env` | 含密钥、端口等设备差异 | 只提交 `.env.example` |
| Docker 数据卷（TDengine/PG/Redis/Qdrant 数据目录） | 体积大、二进制、无版本意义 | 用命名卷，`.gitignore` 排除 |
| 日志、`__pycache__`、`node_modules` | 噪音 | `.gitignore` 排除 |
| 大图片（> 2 MB） | 仓库膨胀 | 压缩后提交；导出图控制在 1600 px 内 |
| 模型权重、数据集 | 体积 | 不入库，用脚本下载 |

## 7. 环境差异管理

两台设备**允许不同**的：端口占用情况、内存可用量、镜像加速地址、大模型 API Key。
两台设备**必须相同**的：目录结构、compose 文件、代码、文档、数据模型。

| 差异项 | 承载位置 |
|---|---|
| 端口 | `.env` 中的 `PORT_*` |
| 内存配额 | `.env` 的 `NODE_MEMORY_BUDGET_GB` + 各自 `C:\Users\<user>\.wslconfig` |
| 镜像加速 | WSL 内 `/etc/docker/daemon.json`（不入库） |
| 模型 Key | 各设备 `.env`（不入库） |

**要求**：`docker-compose.yml` 中不得出现任何绝对路径与硬编码端口，全部走变量。这样任一设备 clone 下来复制 `.env.example` 即可启动。

## 8. 行尾与编码

| 项 | 规则 |
|---|---|
| 行尾 | 仓库统一 LF（`.gitattributes` 强制） |
| 编码 | UTF-8 无 BOM（`.editorconfig` 约束） |
| 文件名 | 中文文件名允许，但脚本内引用必须加引号 |

**常见故障**：Windows 侧编辑过的 `.sh` 带 CRLF，在 WSL 内报 `bash^M: bad interpreter`。解决：

```bash
sed -i 's/\r$//' script.sh     # 或 dos2unix script.sh
```

根治靠 `.gitattributes` 的 `*.sh text eol=lf`。

## 9. 备份与容灾

| 层级 | 措施 | 频率 |
|---|---|---|
| 代码与文档 | GitHub 私有库 | 每次提交 |
| 数据库业务数据 | `pg_dump` 导出到 `docs/../backup/`（不入库） | 阶段结束 |
| 时序数据 | 视为可重建（模拟器可回放），不做备份 | — |
| 决策与状态 | 已入库，git 历史即备份 | 实时 |

**设备损坏的最坏情况**：新设备 `git clone` + 复制 `.env` + `docker compose up`，30 分钟内恢复开发能力。文档与决策不丢，这是「文档先行」的额外收益。

## 10. 同步检查清单（每阶段收尾）

- [ ] `git status` 干净，无未提交改动
- [ ] 已 `git pull --rebase` 确认与远端一致
- [ ] 状态文件已更新为「已验收」并记录 tag
- [ ] tag 已创建并推送
- [ ] 无 `.env`、无数据卷文件被误加入
- [ ] 若本阶段改了端口/依赖，`.env.example` 已同步更新
