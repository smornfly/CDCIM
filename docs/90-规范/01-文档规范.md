### 1.2 文件命名

```
NN-文档名.md
```

- `NN` 两位序号，同目录内连续，**一经确定不复用、不重排**（避免交叉引用失效）。
- 中文名，词间用 `-`，不用空格、不用书名号。
- 示例：`03-项目管理计划.md`、`ADR-0003-大模型接入旁路化.md`。

## 3. 每份文档必须固定的三段结构

**所有文档一律包含以下三部分，缺一不予验收。**

### 3.1 文档头（表格形式，置于标题下）

```markdown
| 项 | 内容 |
|---|---|
| 文档编号 | CDCIM-P1-SRS-01 |
| 版本 / 状态 | v0.1 · 草案 / 评审中 / 已验收 |
| 所属阶段 | P1 需求工程 |
| 论文价值 | ★★★☆☆（1–5 星 + 一句话说明可用在哪段） |
| 上游依据 | 链接到本文件依赖的上游文档 |
```

### 3.2 正文

按该文档类型的标准章节组织（见第 5 节模板索引）。

### 3.3 文档尾（两节，固定标题，供论文直接取用）

```markdown
## 考点映射

| 考纲知识点 | 本文件对应内容 | 论文可用位置 | 真题溯源 |
|---|---|---|---|
| 质量属性场景 | 第 3 节 12 条场景 | 论文「架构设计」段 | 2024 上案例一 |

## 论文可引用段落

> （100–300 字，已润色为论文成稿语言，可直接粘贴。标注适用题目类型。）
```

> **这两节是「文档即论文素材」的落地机制**，不是可选装饰。每份文档都必须写。

## 4. 写作硬规则

| # | 规则 | 说明 |
|---|---|---|
| 1 | **术语对齐考纲** | 统一使用「质量属性 / 架构战术 / 敏感点 / 权衡点 / 效用树 / 4+1 视图 / ATAM / 限界上下文」，不自造同义词 |
| 2 | **决策必须带理由** | 任何「选了什么」后面必须跟「为什么」与「代价是什么」，禁止只列名词 |
| 3 | **量化优先** | 能用数字表达的一律给数字（时延、QPS、可用性、百分比、容量）；无法量化的标注「定性」 |
| 4 | **区分设计与实测** | 设计目标值标「目标」，实测值标「实测」，**严禁把目标值写成已实现** |
| 5 | **诚实边界** | 单机环境无法验证的（等保认证、异地双活、百万测点压测）标注「设计约束，未实测」 |
| 6 | **一图一表优先于长段落** | 结构、流程、对比一律用图或表，正文只写判断与理由 |
| 7 | **交叉引用用相对链接** | 如 `[SRS](02-需求/02-需求规格说明书.md)`（文件建好后再改为真实链接），禁止裸写路径 |
| 8 | **中英文混排** | 中英文之间留半角空格；专有名词首现给全称 + 缩写 |
| 9 | **不写营销语** | 禁止「显著提升」「全面赋能」「行业领先」等无依据表述，改为主语 + 动作 + 数据 |

## 5. 状态与版本

**状态机**：`草案 → 评审中 → 已验收 → 已冻结`（进入下一阶段且被引用后冻结）

**版本号**：`v<主>.<次>`

- 主版本 +1：结构变更、结论变更（如选型改档）
- 次版本 +1：补充、修正错别字、新增图表
- 每份文档末尾必须有「变更记录」表
