## 3. 观测点定义

| 观测点 | 采集方式 | 单位 | 说明 |
|---|---|---|---|
| 采集→总线时延 | 报文 `produced_at` − 设备 `ts` | ms | 契约头字段，不依赖墙钟 |
| 总线→落库时延 | TDengine 写入完成时刻 − `occurred_at` | ms | 从服务端日志取，勿用客户端计时 |
| 落库→可查时延 | smoke 脚本轮询首次返回时间 − 写入完成时刻 | ms | 脚本已记录分段耗时 |
| 队列水位 | `/metrics` 的 buffer usage | % | 80% 应出现一条告警日志 |
| 补传速率 | 补传条数 ÷ 补齐耗时 | 条/秒 | 判据 ≤ 480（稳态 1.2 倍）为**预期区间**，上限 1440 |
| 补传时间戳偏差 | 逐条比对抽样 1000 条 | ms | **必须 0**，非统计容差 |
| 容器内存峰值 | cgroup `memory.peak` | MB | 对照物理视图 mem_limit |

## 5. 失败判定与排查路径

| 现象 | 优先检查 | 处理 |
|---|---|---|
| `make config` 报变量未设置 | `.env` 是否由 `.env.example` 复制、密码是否留空 | 补齐变量，不要改成空字符串 |
| mqtt 容器 unhealthy | `deploy/mosquitto/passwd` 是否生成 | `make init-mqtt` |
| broker 单节点起不来 | Redpanda 需 dev 模式参数 | 检查 compose 中 `--mode dev-container` |
| tsdb 首次启动慢 | TDengine 初始化 4 库耗时 | 拉长 start_period，不要反复重启 |
| api readyz 中 pg=unavailable | `01-postgres.sql` 是否在首次启动执行 | 查 pg 容器初始化日志 |
| 补传时间戳偏差非 0 | 是否有链路给 ts 加偏移 | **禁止加偏移**（D-31），应修代码而非放宽判据 |
| 补传超时 15 min | 是否与在线流量共用 topic | 检查 `telemetry.replay` 是否存在及限速组 |
| nginx 502 | `web/dist` 未构建或 api 未 healthy | `npm run build` 后重启 nginx |
