# ADR-0003　大模型接入：旁路化、脱敏与可降级

| 项 | 内容 |
|---|---|
| 编号 | CDCIM-ADR-0003 |
| 状态 | ✅ 旁路化已确认 / 🟡 云端 API 与脱敏策略默认采纳 |
| 决策人 | 用户提出「必须接入大模型」；架构落点由主智能体设计 |
| 影响范围 | 架构分层、安全设计、可用性战术、论文 AI 相关论述 |

---

## 1. 背景与问题

用户要求项目必须接入大模型能力，且一切按架构师论文要求设计。此处存在一个真实且尖锐的矛盾：

- 动环监控系统是**业务连续性的保障设施**，年可用性目标 99.99%（年停机 ≤ 52.6 min）；
- 大模型 API 是**外部依赖**，存在网络抖动、限流、超时、幻觉、成本五重不确定性；
- 金融行业受等保 2.0 三级约束，业务数据不得随意离开内网。

若把大模型放进告警判定链路，等于把保障系统的可用性交给一个不可控的外部服务——这是架构上的重大错误。因此核心问题不是「要不要 AI」，而是**「AI 放在哪里、以什么方式接入、失败时怎么办」**。

---

## 2. 候选方案

| 方案 | 做法 | 可用性风险 | 合规风险 | 成本 | 评价 |
|---|---|---|---|---|---|
| S1 内嵌式 | 告警引擎每条告警同步调用模型做判定 | **极高**：模型超时即告警延迟，服务不可用即告警停摆 | 高：原始数据外发 | 高：每次告警都调用 | 不可接受 |
| S2 旁路异步式（采纳） | 告警主链路纯规则；模型异步消费告警事件，产出建议写回 | 低：模型不可用时仅建议缺失，告警功能完整 | 中→低：经脱敏中间件 | 可控：事件聚合后调用，量级下降 1–2 个数量级 | **采纳** |
| S3 本地小模型 | 内存内跑 3B 量化模型，数据不出内网 | 中：占用 3 GB+，与 8 GB 配额冲突 | 最低 | 硬件成本高、推理慢 | 因 C-01/C-02 否决（X-02） |
| S4 混合 | 主用云端、本地兜底 | 中 | 中 | 高 | 复杂度不值，原型阶段否决 |

---

## 3. 决策

1. **架构位置**：AI 能力作为独立的「智能层」旁路，消费告警事件主题，输出**建议**（不输出控制指令）。主链路（采集 → 接入 → 计算 → 存储 → 规则告警）零外部依赖。
2. **通道设计**：`告警事件 → 脱敏中间件 sanitizer → AI 代理 ai-proxy → 云端 API`，建议回写告警库的非阻塞字段。
3. **降级策略**：三级降级 —— 超时/限流 → 重试一次后放弃并标记「建议缺失」；连续失败 N 次 → 熔断，10 分钟内不再调用；配置关闭 → 完全跳过。任何一级降级都不影响告警产生与推送。
4. **数据脱敏**：送模型前替换设备真实编号为哈希 ID、拓扑抽象为逻辑层级、去除 IP/机房位置/人员信息；原始数据永不出内网。开关 `LLM_MASK_BEFORE_SEND=true` 强制生效。
5. **Provider 抽象**：适配器 + 策略模式，支持 deepseek / qwen / zhipu / local 四种实现，配置切换，便于成本对比与故障切换。
6. **人在回路**：模型输出仅作建议展示，联动控制必须经规则授权或人工确认。
7. **额度控制**：AI 代理侧做 Token 计量与日配额，超限降级为模板化摘要（不调用模型）。

---

## 4. 理由

1. **可用性优先**：动环系统的第一职责是「不断告警」。任何增加主链路外部依赖的设计都违背 C-14。旁路化把 AI 从「必要条件」降为「增强条件」，是典型的可用性战术（错误隔离 + 降级）。
2. **合规事实约束**：S3 虽最安全，但内存与算力不允许，因此必须在 S2 里用工程手段（脱敏）把风险降到可接受，而不是假装风险不存在。
3. **成本可控**：告警经聚类后调用，量级从「每条告警一次」降到「每个告警簇一次」，Token 成本下降一个数量级以上；再叠加缓存（相同模式告警复用建议）进一步压缩。
4. **论文价值**：「为什么不让大模型进主链路」是一个能体现架构判断力的决策，比「我们用了大模型」有说服力得多。

---

## 5. 代价与缓解

| 代价 | 缓解 |
|---|---|
| 建议有延迟（秒级到十秒级），不能用于实时处置 | 定位为「研判辅助」而非「实时控制」；实时处置仍由规则秒级完成 |
| 脱敏后语义损失，模型判断精度下降 | 保留结构化特征（设备类型、测点类型、告警等级、时间序列形态）而非原始标识 |
| 依赖网络与第三方服务稳定性 | 熔断 + 缓存 + 模板降级；演示时即使断网也能完整展示主链路 |
| 幻觉可能给出错误处置建议 | 输出强制带证据引用（引用了哪些测点与时段）；无证据不展示；人工确认后才可执行 |

---

## 6. 影响

- 组件映射表新增「智能层」：sanitizer、ai-proxy、Qdrant、（可选）Flink。
- P1 需新增 AI 功能需求与验收标准；P2 需在 ATAM 中评估「AI 增强 vs 可用性」权衡点；P3 需产出脱敏规则表与 Prompt 模板。
- 内存：Qdrant 约 250 MB，ai-proxy 约 100 MB（模型在云端，0 本地算力）。

---

## 7. 论文用法

- 适用题目：**AI 原生架构、大模型应用、系统可靠性、安全架构、质量属性权衡**。
- 论述落点：这一段可完整写成「外部智能服务引入后的可用性与合规风险，以及如何用架构手段隔离这些风险」，几乎是现成的案例分析答案。
